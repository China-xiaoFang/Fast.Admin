# Api.Server AI 编码规范

适用于本目录及子目录，与仓库根 `AGENTS.md` 一起使用。

## 工程定位

- `Fast.Admin.sln`：后端项目关系。
- `Directory.Build.props`、`Directory.Packages.props`：共享编译配置与集中依赖版本；同时核对各 `.csproj` 的引用。
- `src/` 中 Domain、Service、Core、Shared 等项目负责不同职责；具体依赖与业务归属按实际代码核实。
- `src/Fast.Api`、`src/Fast.File`、`src/Fast.Scheduler` 等宿主的启动、外部依赖和副作用分别检查，不视为可互换入口。

## C# 与职责划分

- 遵循本目录 `.editorconfig`、共享构建设置和实际语言版本，不将 Fast.NET 的多目标设置机械复制到应用。
- Domain/DTO/服务/宿主职责沿用实际项目边界；不要让实体承载页面交互，不把 HTTP、数据库和业务校验堆入无职责的公共工具类。
- 通过已有 Fast SDK 与应用扩展点组织代码，不重新实现一套依赖注入、响应包装、认证或日志框架。
- 公开接口和共享服务说明必要参数、返回与异常合同；内部业务函数保持适度注释，不为形式引入多层抽象。
- 异步 I/O 保持异步调用链，正确传播取消；不使用无必要 `Task.Run`、阻塞等待或 `async void`。
- 核对 DI 生命周期和资源所有权；不在 singleton/静态对象中缓存请求级用户、租户、连接或 scoped 服务。
- 集中 NuGet 版本与局部引用保持一致，新增依赖先检查已存在的等价能力；不为局部编译问题升级整个框架或关闭 Nullable/分析器。

## 数据与权限

- 租户/机构/数据范围从可信服务器上下文取得，不能只相信客户端传入 ID，也不能只在前端限制访问。
- 查询、详情、导出、批量操作、上传和异步任务应应用其各自需要的数据范围；不能只验证列表查询。
- 验证字段的业务含义、空值、唯一性、枚举与状态转换。并发冲突、重复请求和幂等处理按实际业务明确。
- 事务边界围绕完整业务操作，避免长时间把远程 I/O 包在事务中；不能把缓存成功当作数据库事务成功。
- ORM 查询评估生成 SQL、分页、索引使用、N+1 和大结果集风险；禁止拼接不可信 SQL 或省略权限过滤来优化性能。
- 修改模型不等于获得迁移授权。数据库 SQL/结构方案仅生成供审核，不执行建库、写库、迁移、种子或初始化。

## API、文件与后台处理

- 接口变更同步核对客户端类型和真实调用方，包括统一响应、错误码、分页、日期时区、金额精度和序列化约定。
- 服务端异常保留定位信息，面向用户的响应不暴露堆栈、连接串、文件系统路径或凭据。
- 文件上传/下载验证身份、范围、大小、扩展与实际内容，并约束存储路径；用户提供的名称不能直接决定任意服务器路径。
- 调度、消息和后台处理明确重试、取消、重复执行与并发边界；不要捕获请求 scoped 对象后脱离请求继续使用。
- 运行程序可能触发调度、订阅或初始化。验证优先使用静态检查、编译和安全替身，未经允许不启动连接真实服务的宿主。

## 验证入口

在本目录执行 `dotnet build Fast.Admin.sln -c Release`，先审查自定义构建目标。

有实际测试项目时按其框架/运行器执行相关用例并核对用例数量；没有测试设施时说明验证范围，不把空执行或构建成功当成测试通过。

业务变更覆盖成功、失败、无权限、重复和并发等相关边界。需要补测试或文档时仅处理任务相关内容，不能自行扩展为全工程建设任务。

## 操作边界

仓库根的凭据、数据库、Git、发布和远程操作限制继续适用。编译授权不代表允许执行 `dotnet run`、数据库脚本、部署脚本或修改线上环境。
