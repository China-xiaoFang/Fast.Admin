# App.Admin AI 编码规范

适用于本目录及子目录，与仓库根 `AGENTS.md` 一起使用。本目录是独立的 uni-app 移动管理端工程。

## 工程与业务边界

- 以本工程 `src/main.ts`、页面、路由、状态与插件为入口理解当前实现；从实际管理功能追踪接口和数据权限，不靠 App 名称推断角色权限。
- 管理界面中的操作权限、批量动作、数据范围与后端合同保持一致；移动端展示简化不代表可以弱化授权或业务校验。
- App.Client 可作为相邻实现参考，但不是自动覆盖源；两者的页面、导航、授权和产品行为应分别判断。
- 不因为目录相似就删除本工程、合并依赖或同步整个源码树。需要共享能力时先确认是否适合现有 SDK/组件边界。

## 工具链与启动

- 从本工程 `package.json`、锁文件、Vite/uni-helper 配置、TypeScript、ESLint 与 Prettier 设置读取实际版本和约定。
- DCloud 核心包、Vue、`@vue/runtime-core`、Vite 与相关插件作为兼容组合维护，不能单独升级其中一项来套用 Web 新写法。
- 使用本工程已有的包化 ESLint 接入，不因 SDK 仓库采用其他方式就整套替换配置。
- `src/main.ts` 的 `createSSRApp`、插件、Pinia 和路由注册顺序按现有依赖保持。入口返回类型应表达真实对象，不复制历史 `any` 当作标准。
- 页面、布局、组件声明与平台清单的来源从当前生成配置确认；修改生成输入而不是直接修补会被覆盖的结果。

## 跨平台编码

- 先确定改动影响 H5、App、微信小程序中的哪些平台；共用代码、条件编译和适配层分别处理。
- 不将无条件 DOM、浏览器全局对象或 Node API 引入跨端路径；需要平台能力时使用对应公开 API 或既有适配。
- 页面生命周期、组件生命周期与应用生命周期分别使用。监听、计时器、请求和页面状态的恢复/清理要匹配真实离开与返回行为。
- 路由跳转先核对当前路由封装、TabBar、返回栈、登录重定向和参数约定，不直接照搬 Web Router 的全部语义。
- 平台条件编译和环境变量需检查构建替换结果；缺失值不能在初始化阶段触发无说明的运行时错误。
- 网络、上传、下载、取消、存储和认证通过现有 Fast 请求/平台适配层处理，不创建另一套全局请求和提示机制。
- storage、持久化状态与账号/租户隔离一致；退出和身份切换处理缓存失效，避免跨用户残留。
- 权限、定位、授权或支付等平台能力仅在需求涉及时接入，并处理拒绝、取消和能力不可用；不假定某平台成功等于全端成功。

## Vue、类型与 UI

- 使用当前工具链支持的 Composition API 和类型方式，不能默认采用 Web 端较新 Vue 的专有 API。
- Props、事件与页面参数明确边界；普通页面保持简洁，应用公共组件提供必要类型，不靠断言掩盖接口不一致。
- UI 延续本工程 Wot 与现有组件/布局，使用适合各平台的样式单位、滚动容器、弹层和安全区处理。
- 不将 Element Plus 或仅浏览器可用组件直接搬入跨端页面，也不为视觉统一更换全套 UI。
- 验证 loading、空数据、失败、键盘、长文本和相关安全区状态；不要通过截图好看推断交互正确。
- API 接口类型、枚举和金额/日期含义与后端合同一致；接口报错与平台授权失败不能混成同一种成功状态。

## 验证入口

```text
pnpm run typecheck
pnpm run lint
pnpm run format:check
pnpm run check
pnpm run build:h5
pnpm run build:app
pnpm run build:mp-weixin
```

以当前 `package.json` 为准，只选择受影响且环境可执行的平台；构建脚本可能已经包含 `check`。

H5 构建、小程序开发工具验证、App 编译产物和真机验证分别记录。环境缺失时明确未验证的平台，不将一种通过写成全部通过。

测试和文档按任务范围使用现有设施，不因局部页面修改自动引入全套框架。日常验证不使用真实账号、支付、数据写入或外部服务副作用。

## 注释与操作边界

跨平台限制、兼容原因和生命周期边界应保留必要注释；不逐行解释直观代码，不把 SDK 文档密度套入所有页面。

根 `AGENTS.md` 的凭据、数据库、Git、发布和远程操作限制继续适用。平台配置中的可公开标识与私钥/Secret 不同，不能把敏感凭据写入页面、清单、示例或日志。
