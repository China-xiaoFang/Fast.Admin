# Web.Admin AI 编码规范

适用于本目录及子目录，与仓库根 `AGENTS.md` 一起使用。本工程是 Vue 3、TypeScript、Vite 与 Element Plus/Fast 组件体系的 Web 管理端。

## 阅读入口与目录职责

- `package.json`、锁文件、Vite、ESLint、Prettier、TypeScript 配置：实际工具链与检查入口。
- `src/main.ts`、`src/App.vue`：启动、插件、状态、路由与主题加载。
- `src/views/`、`src/components/`、`src/layouts/`：页面、应用公共组件与布局。
- `src/api/`、`src/stores/`、`src/router/`：接口封装、状态与导航。
- `src/plugins/`、`src/directives/`、`src/styles/`、`src/signalR/`：扩展、样式与实时连接能力。

## Vue、TypeScript 与状态

- 沿用 Composition API 与现有 SFC/TSX 组织。普通页面保持简洁，公共组件则提供稳定的 Props、Emits、Slots 和实例合同。
- 新语法与 API 必须匹配本工程 Vue、构建插件和类型工具链；不因示例使用某个新 API 就提高最低版本。
- 使用类型推断与精确边界，不引入无意义泛型、`any` 或断言；需要精确事件与 slot 参数时通过真实类型表达。
- props 通过事件或 `v-model` 协作更新；避免直接修改输入对象，也不要复制出失去同步的表单或列表状态。
- 派生值优先使用合适的计算关系；副作用用明确生命周期/watch。避免互相写入的 watcher、重复请求和深度监听滥用。
- TSX 使用 Vue 的 ref、`class`、事件与 slot 语义；事件属性传处理函数，不在渲染时提前执行请求或提交。
- 异步处理保留自然 `async/await`，在正确边界恢复 loading 与展示错误；组件卸载后清理监听、定时器和属于该组件的资源。
- Pinia 持久化只保存需要且适合持久化的数据。切换账号或租户时处理权限、菜单、缓存和持久化状态的失效。

## 接口、路由与权限

- 接口通过现有 API/request 层与 Fast.Axios 约定接入，不在页面创建另一套 Axios 实例、重复拦截器或独立全局错误处理。
- 保持启动时状态、插件与路由初始化的依赖顺序。调整入口不能让守卫在用户/租户状态尚未准备好时误判。
- 路由权限和菜单权限区分展示与访问控制；客户端校验不替代服务端授权。
- API 类型与服务端真实字段一致，明确分页、日期、枚举和错误处理；不要将不确定的响应强转成页面需要的形状。
- 生成组件声明、路由元数据等先检查生成源和 Vite 配置，不直接修改生成文件作为永久修复。
- SignalR 等长连接区分全局与页面所有权，避免重复订阅；退出、重连和身份变化时正确处理连接状态。

## UI 与样式

- 优先复用 Fast/Element Plus 现有组件与应用公共组件，不为某个页面引入第二套 UI、表格、表单或弹层体系。
- 复用既有主题变量、深浅色机制和样式入口；避免无关全局样式、过度选择器权重和滥用 `!important`。
- 表格、分页、筛选、表单、弹层等按实际已有数据与状态合同协作，不把动态配置改成静态硬编码以贴近设计图。
- 处理加载、禁用、校验、空数据、失败、溢出和相关响应式状态；可操作元素支持适当语义、键盘与焦点反馈。
- 不因代码整理改变视觉风格、文案含义或交互流程；设计调整以明确需求为范围。

## 验证入口

```text
pnpm run typecheck
pnpm run lint
pnpm run format:check
pnpm run check
pnpm run build
```

命令以当前 `package.json` 为准；`build` 已可能包含 `check`，不要无意义重复执行。UI 修改在环境允许时检查受影响页面，不能只用类型检查代替交互验证。

不默认新增测试/文档框架；使用已有设施验证相关变化。缺少可运行页面、账号或隔离环境时明确报告，不连接真实服务执行有副作用操作。

## 注释与安全

公共组件与共享类型说明合同，页面内部注释以原因和业务边界为主，不要求每个函数完整 TSDoc。短标签不机械加句号，完整陈述正常使用标点。

仓库根的安全边界继续适用。前端环境变量与构建产物可能对使用者可见，不放入服务端秘密；日志与错误详情不得泄露凭据或敏感业务数据。
